疊 Kasanemu Phase 1

自己安裝、自己付 API 帳單的疊層翻譯。譯文是主體,原文是備查; 不改動網頁 DOM 與 CSS。 第一次使用請先讀說明書。

金鑰與語言

存在 chrome.storage.local。瀏覽器 profile 即信任邊界,無任何自架後端或遙測。

漸進式翻譯

L0 是 Chrome 內建的 Translator API:本機、毫秒級、零成本,疊層立刻出現; L1 是 Gemini / Gemma 的譯文,回來之後就地替換。 single 是 Phase 1 的行為,保留為對照組; l0-only 是零成本離線模式,不是除錯選項。 模式以網域為單位記憶,在 popup 切換。

預設是關的。啟用只代表「這個網域我要用 Kasanemu」—— 真的要翻是另一個動作:popup 的「翻譯這一頁」或 Alt+R。 在同一頁點連結跳轉後也要再按一次:你按的是「翻**這一頁**」, 不是「從今以後每一頁」。 競品多半一進站就整頁翻,想要那種行為就把這個打開。 滑過去 / 選起來的加翻不受這個開關影響 —— 指到什麼就翻什麼本身就是明確的動作。

這一條是成本控制的關鍵:純粹滑過去的區塊留在 L0,不花錢。 設成 0 等於整頁都升級,LLM 呼叫量會比「只翻可見區」更多。

來源語言優先看**畫面上的文字**:假名 → 日文、諺文 → 韓文、漢字 → 中文。 <html lang> 只在字集判不出來(整頁拉丁字母)時才採用 —— 樣板留下來的 lang="en" 很常見,而 Translator API 的 sourceLanguage 是宣告不是偵測,弄錯了它不會報錯,只會安靜地吐出垃圾。 整頁都是拉丁字母時分不出英文 / 法文 / 德文,那時才用這個值。

詞表

一行一條。原文 → 譯法 固定譯法;只寫原文就是「不翻」; 結尾加 ! 是大小寫敏感(縮寫用);# 開頭是註解。
詞表的做法是送出前換成私用區佔位符、翻完再換成你指定的說法 —— 模型從頭到尾沒看到那個詞,所以每個檔位都有效,連 L0 都有效。 代價是周邊語法不會跟著調整:請登記完整的名詞片語 (寫 attention mechanism,不要只寫 attention)。
行內 <code>、kbd、samp、 translate="no" 自動納入保護,不必列在這裡。

網域寫 example.com 是完全相同,*.example.com 連主網域一起算, * 是全部。一個網域可以掛多份,結果是聯集。
為什麼不是每個網域各一份清單: kubernetes.io、qiita.com、zenn.dev 要保護的是同一批術語。逐一設定等於同一份清單抄很多遍,而且新網域永遠是空的。

額外請模型在句子裡自己安放詞表說法,語法比佔位符通順。 關掉不代表詞表失效 —— 詞表一律以佔位符生效, 這個開關只決定要不要「額外」請模型配合。 實測(scripts/probe-glossary.mjs)三個檔位的遵循率都是 100%、 對 id 紀律零影響,所以自動模式三檔全開;換模型之後要重跑那支腳本再決定。

詞表是手工整理出來的東西 —— 快取弄丟了再花一次錢就回得來, 詞表弄丟了只能重打,所以它有自己的匯出匯入(快取那組不含詞表)。 匯入是同名的以檔案為準,本機獨有的保留: 還原備份時你要的是檔案裡的版本,而不是「只補不覆蓋」。

三檔模型

模型 ID 會在啟動時與 GET /v1beta/models 比對;不存在的 ID 標紅, 不要等到執行時才 400。gemini-3.6 系列一律拒收:實測有 batch 內 id 對滑。

視覺

疊層的盒子等於原文的 border-box,但字的墨水範圍由字型的 ascent / descent 決定 —— 行距壓得很緊的大標,第一行的頂端與最後一行的 g 尾巴會落在盒子外面, 看起來像沒蓋乾淨。那一部分會用字型度量自動補足;這個值是再多加的固定量, 給 text-shadow、斜體尾巴這類量不到的東西。加太多會蓋到相鄰區塊。

用 elementFromPoint 確認來源元素在它自己的位置上打得到。 擋掉被 overflow: hidden 裁掉的重複 DOM(輪播的另一份、 隱藏的行動版選單)—— 那種疊層會浮在完全無關的位置上。 頁面若有透明的點擊攔截層可能誤判,那時關掉。

Gmail 這種應用程式的捲動發生在內層容器裡,而疊層畫在 document 座標上 不會跟著動 —— 不透明的盒子就畫到別人的內容上。那種頁面只能「捲動時先藏起來, 停下來再一次量、一次顯示」。 但同一條規則套在一般長文上只換來閃爍:文章的段落在 document 座標裡 根本不會因為捲動而移動。
自動不看網域看行為:document 自己不捲,或這一頁真的收到過 內層容器的捲動事件,才啟用。白名單列不完,而且會漏掉沒列到的網站。
一直顯示是「我不在意偶爾不對齊,不要閃」; 嚴格是舊行為,版面很動態的頁面上最保守。

24 字以內的按鈕與連結不會被疊層覆蓋 —— 譯文比原文短,盒子要嘛蓋掉項目之間的 間隔,要嘛讓原文從右邊露出來,兩種都難看。改成滑過去時在**旁邊**出一塊不透明 貼片,原文一個像素都不動。停留 0.2 秒才出現,所以橫掃導覽列不會沿路閃。 貼片不吃滑鼠事件,就算蓋到隔壁按鈕,那顆按鈕照樣點得到。

疊層背景永遠不透明:底下是活文字不是死像素,半透明會讓兩層字互相干擾, 所以這裡沒有透明度旋鈕。

快取

快取的 key 是原文 + 目標語言 + 模型 ID + 長度分桶,不綁網域 —— 所以同一句話在不同頁面上也會命中(導覽列、頁尾、重複的標題命中率特別高)。 換檔位等於換模型 ID,那是另一份譯文,不會互相污染。
persistent 存在 IndexedDB,關掉瀏覽器、重開機都還在,超過下面的 上限才依最久沒用到的順序清掉。session 只留在記憶體與 chrome.storage.session,瀏覽器一關就沒了 —— 重新載入擴充功能也會清空,所以封測期間換 build 之後第一次翻一定是全新的。

譯文是花錢換來的,不該綁在安裝上。換版、重灌、換機器前先匯出, 裝好之後匯回來就不必重翻。
匯入是只補不覆蓋:同一把 key 代表同一段原文 + 同一個模型 + 同一個長度分桶,現有的那份不會比較差,而覆蓋會把剛翻好、還熱著的換成檔案裡的舊資料。
