疊 Kasanemu 封測 · 0.1.0

把譯文疊在原文上,不動網頁一根汗毛

Kasanemu 不重寫網頁,也不開側欄。它在頁面正上方畫一層不透明的譯文, 蓋住原本那段外文;滑鼠移過去,譯文讓開,原文就在原位。

疊層示範 滑鼠移上去看原文

The extension paints an opaque layer directly over the original text. Nothing in the page is rewritten, so the site keeps its own layout and behaviour.

這個擴充功能直接在原文上方畫一層不透明的疊層。頁面本身沒有任何東西被改寫, 所以網站保有它自己的排版與行為。

上面這塊是純 CSS 的示意。真的裝起來之後,每一段外文都會這樣被蓋住, 而且疊層完全不吃滑鼠事件 —— 網頁上的連結、按鈕照常可以按。

概念

兩層翻譯,快的先上,好的後到

翻譯分兩階段,你會親眼看到它換一次:

L0 · 本機即時層

Chrome 內建的翻譯模型,在你的機器上跑。毫秒到幾秒之間,零成本、離線可用。疊層先用它把畫面填滿。

L1 · 升級層

Gemini / Gemma 的譯文。回來之後就地把 L0 換掉,你只會看到那一塊文字變好。

為什麼要有兩層 L0 快但生硬,L1 好但要等(而且可能要錢)。先給你看得懂的東西,再默默換成更好的 —— 比起盯著空白等 API,這樣好用得多。
語言

不只英文:日文、韓文也翻

翻譯目標固定是繁體中文(可在設定改),來源語言則是看畫面上的文字自己判斷的: 有假名就是日文,有諺文就是韓文,整頁拉丁字母就照 <html lang> 或設定的預設值走。

來源L0 本機層L1 升級層
英文主要測試對象可以
日文看你的 Chrome 有沒有 ja 語言包可以
韓文看你的 Chrome 有沒有 ko 語言包可以
其他拉丁語系需要在設定指定來源語言可以

L1 是 LLM,給它什麼語言都翻得動。L0 是 Chrome 的內建模型, 該語言對沒有語言包就會整批失敗 —— 那時提示線會是警示色, 但 L1 仍然會接手,只是第一眼要等比較久。

日文頁面的一個細節 日文標題常常是純漢字、一個假名都沒有(「東京都知事選挙」)。 單看那一塊會誤判成「已經是中文」而跳過,所以語言是整頁判一次的。 真的遇到日文站標題沒翻,那是 bug,請回報網址。
前置

先確認你的機器

  • 桌機版 Chrome。手機版沒有擴充功能。
  • Chrome 138 以上才有 L0(內建 Translator API)。版本在 chrome://version 看得到。
  • 沒有 L0 也能用 —— 擴充功能會自動退回「全部走 L1」,只是第一眼會等比較久。
  • 第一次用 L0 時 Chrome 需要下載語言包(幾十 MB),而且必須由你按一下才會開始下載。popup 上會出現「下載 L0 語言包」的按鈕。
低階機器會明顯比較慢 L0 是在你的 CPU 上跑的。同一個頁面在 Windows 桌機幾乎是一口氣翻完, 在入門款 Chromebook 上每塊要好幾秒。這是正常的,不是壞掉。
五個步驟

安裝

  1. 解壓縮你拿到的 zip

    解出來會是一個資料夾,裡面有 manifest.json。把它放在一個之後不會被你刪掉的位置 —— Chrome 是直接讀那個資料夾,搬走或刪掉擴充功能就會失效。

  2. 打開 chrome://extensions

    網址列直接貼進去。

  3. 右上角打開「開發人員模式」

    這是封測版的必要條件:沒有上架 Chrome 線上應用程式商店,只能以未封裝的形式載入。

  4. 按「載入未封裝項目」,選剛才那個資料夾

    選資料夾本身,不是裡面的 manifest.json。成功的話清單上會出現「Kasanemu」。

  5. 把它釘在工具列上

    按網址列右邊的拼圖圖示,找到 Kasanemu,按圖釘。之後所有操作都從這個圖示進去。

上手

第一次使用

預設值已經幫你設好了:progressive 管線(L0 打底 + L1 升級)加上 free 檔位(用免費的 Gemma,不會產生帳單)。所以第一次只有一件事要做 —— 填 API key。

  1. 拿一把 Gemini API key

    到 Google AI Studio 建立,免費。free 檔位用的模型在免費額度內。

  2. popup → 「設定」→ 貼上 key

    順便確認「目標語言」是 zh-TW。設定會自動存,不用按儲存。

  3. 回到任何外文網頁,按 Alt + T

    或按 popup 上的「啟用」。啟用狀態是記在網域上的 —— 這個站以後自己會開,別的站不受影響。

啟用不等於開始翻 預設不會自動翻。啟用只代表「這個網域我要用 Kasanemu」; 要翻是另一個動作 —— popup 的「翻譯這一頁」或 Alt+R。 在同一頁點連結跳轉後也要再按一次: 你按的是「翻這一頁」,不是「從今以後每一頁」。 想要競品那種一進站就整頁翻的行為,popup 上把「每一頁都自動翻」打開。
沒按也能問單一段落 滑過去、或把字選起來的加翻不受這個開關影響 —— 指到什麼就翻什麼本身就是明確的動作,而且一次只有一小塊。
介面

畫面上的東西怎麼讀

左下角的狀態列

翻譯中、翻完了、還是壞了,狀態列都會講。常見的幾種:

⋯ 疊 · L0 12 · 等升級 5 12 塊已經有 L0 譯文,5 塊正在等 L1 回來。
疊 · L0 3 · L1 14 · 完成 整頁都處理完了。狀態列說完就會自己淡出 —— 常駐的狀態列是噪音。
疊 · L1 14 · 這一屏完成,捲動繼續翻 你看得到的都好了,頁面下面還有沒輪到的。那不是漏掉,是還沒要。
✗ 疊 · L0 9 · L1 6 · 失敗 2 · 滑到紅線上重試 有 2 塊翻不出來。把滑鼠停在那塊上就會自動再試一次。
疊 · 沒找到可翻譯的區塊 整頁沒有夠長的英文段落,或內容還沒載入完。

譯文左邊那條細線

線的樣子就是那一塊的狀態,不用打開任何面板:

細實線、很淡
L1 譯文,這是最終品質。
斜紋 / 虛線
還停在 L0。可能正在等升級,也可能因為你只是滑過去、沒停留,所以不花錢升級。
警示色實線
L1 掛了,但 L0 的譯文還在,你看得懂。
警示色虛線
兩層都失敗,那一塊只剩原文。滑上去會自動重試。

兩個隨手可用的動作

  • 滑鼠移到譯文上 → 疊層讓開,原文回來。移開就換回譯文。
  • 按住 Alt → 整層暫時收起,整頁原文一次看光;放開就回來。
加翻

導覽列、按鈕、選起來的字

24 字以內的按鈕、分頁、選單、連結不會被疊層蓋住。 理由很實際:譯文比原文短,盒子要嘛蓋掉項目之間的間隔、把整條導覽列擠歪, 要嘛讓原文從右邊露出來變成「聯絡業務ales」。兩種都難看。

所以它們走另一條路 —— 滑上去停 0.2 秒,譯文出現在旁邊, 原文一個像素都不動。移開就消失。

指到什麼就翻什麼。不只按鈕和連結 —— 任何一段沒有被疊層接手的 文字,滑上去停一下都會出貼片。翻不到的時候還有更直接的一招: 把那段字選起來,譯文立刻出現,不必等停留。 選取可以跨越好幾個元素,所以連「半句話」都問得到。

  • 橫掃不會閃。要停留才出現,所以滑鼠掃過一整排導覽列不會沿路冒出貼片。
  • 選起來就翻。選取是最明確的「我要這一段」,所以不等 0.2 秒,選完就出;點一下別的地方取消選取,貼片才消失。
  • 重複的字只翻一次。卡片牆上十二張卡都寫「詳細を見る」,十二張都 hover 得到,但只送一次 API。
  • 第二個開始不用等。一旦有貼片開著,移到隔壁項目會立刻換。
  • 點得到。貼片和疊層一樣不吃滑鼠事件,就算蓋到隔壁按鈕,那顆按鈕照樣點得到。
  • Alt+Shift+H 全部顯示。和掃視疊層同一組鍵,一眼看完整條導覽列。
  • 鍵盤也有。用 Tab 移到連結上,貼片一樣會出現。
花費怎麼算 貼片是注意力驅動的:沒停留過的標籤一毛不花。 停留超過 0.6 秒才會送 L1,而且是把同一組(整條導覽列) 一起送 —— 一次批次比十次單筆便宜,滑到第二個時譯文已經在了。 不想被打擾的話,設定裡可以改成「只在按住 Alt 時出現」,或整個關掉。
自訂

詞表:固定某些詞怎麼翻(或不翻)

設定頁的「詞表」可以指定某個詞一律譯成什麼, 或是某個詞一律不要翻。一行一條:

寫法意思
embedding → 嵌入向量一律譯成「嵌入向量」
Kasanemu只寫原文 = 不要翻,原樣留著
IT!結尾加 ! = 大小寫要一模一樣才算(縮寫用)
# 這是註解# 開頭的行會被忽略
請登記完整的名詞片語 寫 attention mechanism → 注意力機制,不要只寫 attention。只登記半個片語的話,剩下那半仍然會被翻一次, 結果變成「注意力機制 機制」。這是這個做法唯一的代價。

三層:全域、具名詞表、綁定

  • 全域詞表 —— 所有網站都生效。放你的名字、產品名、 不管在哪裡都不該被翻的東西。
  • 具名詞表 —— 用 === 技術 起一份新的, 底下寫那一類的術語。可以有好幾份(技術、財經、遊戲…)。
  • 綁定 —— 一行一條 *.qiita.com → 技術, 把詞表掛到網域上。example.com 是完全相同, *.example.com 連主網域一起算,* 是全部。 一個網域可以掛好幾份,結果是加起來。

為什麼不是每個網域各一份清單: kubernetes.io、qiita.com、zenn.dev 要保護的是同一批術語。逐一設定等於同一份清單抄很多遍, 而且每遇到一個新網站都要從頭再打一次。

為什麼每個檔位都有效,連 L0 也有效 做法是送出前把那個詞換成一個特殊字元、翻完再換成你指定的說法 —— 模型從頭到尾沒看到那個詞,所以它不需要「聽話」。 這也是為什麼連沒有指令通道的 L0(本機翻譯)都遵守詞表。

設定裡還有一個「把詞表也寫進 prompt」的開關,預設是「依檔位自動」。 它是額外請模型在句子裡自己安放說法,語法會更順。 關掉不代表詞表失效 —— 上面那條路一直都在。

備份與還原

詞表底下有「匯出詞表」與「匯入詞表」兩顆按鈕, 存成一個 .json(檔名帶日期)。

  • 換版、重灌、換機器前先匯出。快取弄丟了再花一次錢就回得來, 詞表弄丟了只能重打 —— 這是它值得單獨備份的理由。
  • 匯入是「同名的以檔案為準,本機獨有的保留」。 還原備份時你要的就是檔案裡那個版本;本機另外加的詞表不會被清掉。
  • 和「匯出快取」是兩回事。快取那組只有譯文,不含詞表; 詞表這組只有詞表,不含譯文。兩個都想留就兩個都按。
改了詞表之後 已經畫在畫面上的譯文不會自己更新(那要重新花錢)。 按 Alt+R 重翻這一頁就會套用新的詞表。 快取有跟著詞表分開存,所以重翻不會拿到舊的那份。

popup 上會顯示這個網域命中了哪幾份詞表、共幾條 —— 「設了沒生效」和「網域沒對上」看起來一模一樣,所以那一行要看得到。

操作

快捷鍵

按鍵做什麼
Alt+T在這個網域啟用 / 關閉疊層翻譯
Alt+Shift+T切換「全開」/「點閱」(點閱 = 疊層平常隱藏,滑過才顯示)
Alt+R翻譯這一頁。再按一次會把失敗的重試、還停在 L0 的全部升級(包含收折起來的內容)
按住 Alt暫時收起整層 —— 想瞄一眼原文就按著,放開就回來
Alt+Shift+H掃視:疊層切成標註樣式,同時顯示所有 UI 標籤的貼片(除錯用)
Alt+Shift+D抽樣面板:原文 / L0 / L1 三欄並列(需先在設定開 debug mode)

快捷鍵撞到別的擴充功能的話,到 chrome://extensions/shortcuts 改。

成本

檔位與帳單

檔位決定 L1 用哪個模型,一樣記在網域上。封測預設是 free。

檔位模型費用什麼時候用
free gemma-4-31b-it 免費 預設。零帳單,但免費層的速率限制很緊,長頁面會排隊
balanced gemini-3.5-flash-lite 低 日常瀏覽。品質與速度的平衡點
quality gemini-3.5-flash 較高 要認真讀進去的長文、術語密集的技術文件

帳單不會失控的三道關

  • 不按就不翻。預設不自動翻,連 L0 都不跑。整頁翻譯永遠是你主動按出來的。
  • 停留才升級。一個區塊要在畫面上待滿 1.5 秒才會送去 L1。純粹捲過去的段落留在 L0,一毛不花。
  • 每頁 token 上限與每日預算。預設每日 60 元台幣,超過就停。popup 上隨時看得到今日 / 本月花了多少。
  • 供應商端的硬牆。擴充功能管不到這一層,但這是唯一真正擋得住失控的東西 —— 請自己到 Google Cloud 配額頁設專案層的日配額。
想完全不碰網路 popup 把管線切成 l0-only。全程本機、零成本、離線可用,連 API key 都不需要。
隱私

你的 key 去了哪裡

  • API key 存在 chrome.storage.local,只在你這台機器的 Chrome profile 裡。
  • 沒有任何自架後端、代理或遙測。擴充功能只跟 Google 的 API 講話,用的是你自己的 key、你自己的額度。
  • 要翻的文字會送到 Gemini / Gemma。這代表不要在需要保密的內部系統上開它。
  • L0 完全在本機,不出網路。
  • 匯出的診斷 log 會把 key 遮成前後各兩碼,所有文字截到 60 字 —— 可以直接貼給我。
除錯

出問題的時候

某幾塊變紅了

把滑鼠停在那塊上約半秒,它會自己重排隊重翻(每塊最多兩次)。整頁都要重試就按 Alt+R。

狀態列說「沒找到可翻譯的區塊」

多半是內容還在載入,或那一頁是無限捲動的。捲一下、或重新整理。真的整站都這樣,請回報網址。

L0 一直是「需要在 popup 按一下」

Chrome 規定語言包下載必須由使用者手勢觸發。打開 popup 按「下載 L0 語言包」,等進度跑完。

疊層位置歪掉、蓋到別的東西

這是最需要回報的類型。請截圖 + 匯出 log,並且說一下當下在做什麼(剛捲動?剛展開選單?)。

換版、重灌之前先備份

兩個東西要分開備份,而且合併方式相反。

  • 設定 → 快取 → 匯出快取(譯文)。匯入是 只補不覆蓋 —— 現有的譯文不會比較差, 倒回舊檔不該蓋掉你剛翻好的。
  • 設定 → 詞表 → 匯出詞表(你自己整理的術語)。匯入是 同名的以檔案為準 —— 還原備份時你要的就是檔案裡那個版本。

快取弄丟了再花一次錢就回得來,詞表弄丟了只能重打 —— 所以詞表其實比快取更值得先按那顆按鈕。詳見 詞表那一節。

把翻好的這一頁存下來

popup → 匯出這一頁(疊好的),存成一個 .html。 打開就是譯文版,滑過去或按住 Alt 一樣看得到原文 —— 和使用中的行為一致,只是改由三行 CSS 兌現,不需要擴充功能也能看。
兩個限制:頁面自己的 <script> 會被拿掉(不然框架重新 渲染時會把譯文洗掉),而樣式與圖片仍然向原站取用 —— 離線開只剩文字。

同一頁重開,會不會再花一次錢?

不會。譯文快取預設存在磁碟上(IndexedDB),關掉瀏覽器、重開機都還在, key 是「原文 + 目標語言 + 模型 ID + 長度」而且不綁網域 —— 同一句話在別的頁面上也會命中。診斷 log 有一行「快取:命中 N 塊」可以看。
例外是換 build:重新載入擴充功能會把記憶體與 session 的部分清掉, 所以封測期間每換一版,第一次翻都是全新的。

說「完成」了,卻還有幾塊只有 L0

那是刻意的:一個區塊要在畫面上待滿 1.5 秒才會送去 L1, 純粹捲過去的段落留在 L0,一毛不花(提示線是虛線)。
想把那幾塊也升上去,再按一次 Alt+R (或 popup 的「翻譯這一頁」)—— 它會把還停在 L0 的全部送去升級。 狀態列在這種時候會直接寫出來還有幾塊。

「未升級 N」是什麼意思

那幾塊的 L1 沒回來,但畫面上有 L0 的譯文 —— 你讀得懂, 只是品質停在本機那一層(提示線是虛線)。免費檔位偶爾會對某幾段吐空回應, 那不是壞掉。想再試一次就把滑鼠停在那塊上。
真正沒有東西可看的會寫「失敗 N」,那時狀態列才會是警示色。

狀態列不見了,是不是死掉了?

說完就淡出是刻意的 —— 常駐的狀態列是噪音。但有失敗的時候它不會淡出, 會一直留著直到那幾塊被重試成功。所以:狀態列不在 = 沒有待辦,不是當掉。 想確認的話打開 popup,那裡永遠看得到這一頁的即時統計。

捲動時譯文一直閃

Gmail 這種頁面的捲動發生在內層容器裡,疊層畫在頁面座標上不會跟著動, 所以那種頁面必須「捲動時先藏起來,停下來再顯示」。一般長文不需要,預設也不會這麼做。 如果你在某個網站上還是覺得閃,到選項 → 視覺 → 捲動時的疊層穩定策略 改成「一直顯示」;反過來,版面很動態的頁面可以改成「嚴格」。

回報的標準流程 popup → 「匯出診斷 log」→ 內容會複製到剪貼簿,存成 .md 直接貼給我。 裡面有版本、build 編號、頁面資訊、時間軸與錯誤,不需要你再描述細節。 有畫面問題的話,截圖一起附上。

已知限制,以及我想知道什麼

目前確定不完美的地方

  • 很短的 UI 標籤不用疊層蓋,改成滑過去顯示貼片(見上面「導覽列與按鈕」)。
  • 行距壓得很緊的大標,偶爾第一行頂端或 g、p 的尾巴會露出來一點。
  • 非常動態的頁面(輪播、展開動畫)在動的當下,疊層可能慢半拍才跟上。
  • 分享列、.notranslate 標記的區塊一律不翻 —— 那些不是內容。
  • 網頁應用程式的介面外殼(導覽列、工具列、Gmail 左欄那種)不蓋疊層,但滑上去仍然翻得到。
  • 在 <div> 裡面捲的頁面(Gmail、Slack),捲動時疊層會暫時消失,停下來就回來 —— 那是刻意的,總比疊層跟著滑好。只有那種頁面才這樣,一般長文捲動時譯文一直都在;真的還是覺得閃,設定裡可以改(見上面「出問題的時候」)。
  • free 檔位在長頁面上會明顯排隊,那是免費層的速率限制,不是當掉。
  • 日文與韓文是「應該會動」而不是「測過了」—— 封測的主力測試對象是英文。

最想收到的回饋

  • 位置類的錯:疊層蓋錯地方、蓋掉圖片、跟著捲動抖動。截圖 + log。
  • 速度體感:你捲到的時候,那一段翻好了嗎?還是還在等?
  • L0 到 L1 的替換:字換掉的那一瞬間會不會打斷你閱讀?
  • 加翻貼片:0.2 秒的等待感覺對嗎?貼片出現的位置擋到你要看的東西了嗎?
  • 還有哪裡滑上去不會翻:網址 + 那段文字,這是現在最想知道的。
  • 日文 / 韓文站:有翻嗎?來源語言判對了嗎?(log 裡的 sourceLang 會寫)
  • 哪些站完全不能用:網址就好。
  • 詞表:有哪個詞你設了卻沒生效?(popup 上那行「詞表 … N 條」有顯示嗎?)
