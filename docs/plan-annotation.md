# 加翻層(annotation layer)—— 計劃

> 狀態:**兩階段都已實作**。第一階段(UI 標籤)在這份文件之後做,
> 圖片加註接在同一個介面上(`docs/plan-images.md`,v0.2.0)。
> 這份文件同時是「為什麼」的紀錄,和那個介面約定本身。

## 0. 一句話

疊層有兩種,不是一種:

| | **疊翻**(既有) | **加翻**(新) |
|---|---|---|
| 對象 | 內文段落 | UI 標籤、選單、連結 → 之後是圖片裡的字 |
| 手法 | 不透明覆蓋,取代原文 | 不透明**貼片**,放在旁邊,不取代 |
| 生命週期 | 常駐 | 暫態(hover / focus / Alt 才出現) |
| 幾何風險 | 高(要蓋準) | 低(不必蓋準,只要放得下) |
| 原文 | hover 才拿得回來 | 一直在,從沒被蓋住 |

兩者共用 L0 → L1 的管線、快取、id 紀律與成本保險絲。差別只在**渲染與觸發**。

## 1. 問題

`detect.ts` 的 `isUiLabel()` 現在把「24 字以內的互動元素文字」整批排除:
導覽列、按鈕、分頁、選單項目、卡片上的 CTA。理由寫在原註解裡 ——
按鈕是疊層最容易出事的地方(hover 位移、隱藏的行動版複本、輪播複製),
Margin 乾脆整個不翻,我們取中間值以長度分辨。

那個決定到今天仍然對:**用疊翻去蓋 UI 標籤就是會壞**。
但「不翻」也不對 —— 使用者看不懂 `Deploy` 旁邊那顆 `Rollback` 是什麼,
而那正是他最需要看懂的字。

## 2. 為什麼不能直接用現有的疊層去蓋

兩個獨立的理由,任何一個都足以否決。

**幾何。** 譯文比原文短很多(英文 `Contact sales` 13 字 → 中文「聯絡業務」4 字)。
盒子有兩種畫法,都難看:

- 盒子 = 原文寬度 → 蓋掉了原文右邊的留白,而導覽列的留白就是**項目之間的間隔**,
  於是相鄰項目被吃掉一角,整條列看起來歪了
- 盒子 = 譯文寬度 → 原文從右邊露出來,變成「聯絡業務ales」

內文沒有這個問題,因為內文是整塊的、右邊沒有東西。UI 標籤右邊永遠有東西。

**不透明是硬規則。** PRD §2.2:疊層背景永遠不透明,底下是活文字不是死像素,
半透明會讓兩層字互相干擾。所以「淡淡的疊上去」**不能**用 alpha 實作 ——
兩層字疊在一起是糊的,不是淡的。

> 「淡」要重新定義成**視覺重量低**,不是不透明度低:
> 小字級、低彩度、貼著原文但不壓在原文上、而且**只在被指名時出現**。

## 3. 四條原則

1. **不蓋原文。** 加翻是加法。原文一直在原位,一個像素都不動。
2. **暫態優先。** 預設什麼都不畫。使用者指名(hover / focus / 按住 Alt)才出現,
   移開就消失。看錯的成本因此永遠是「移動一下滑鼠」。
3. **穿透無害。** 疊層是 `pointer-events: none`,所以貼片就算蓋到隔壁的按鈕,
   使用者**照樣點得到那顆按鈕**。這讓放置策略可以放鬆 ——
   我們要避免的是視覺遮擋,不是功能遮擋。
4. **共用管線。** L0 打底、L1 升級、快取、id 紀律、成本保險絲一條都不另開。
   加翻只是同一批譯文的另一種畫法。

## 4. 互動設計

### 4.1 觸發與時機

| 事件 | 行為 |
|---|---|
| 指到 UI 標籤,停留 **180ms** | 開貼片 |
| 已經開著,移到同組的另一個標籤 | **立刻**換,不重新等 180ms |
| 移開 | 延遲 **80ms** 才關 |
| 貼片開著滿 **600ms** | 把**整組**排入 L1 |
| 捲動後 **300ms** 內 | 不開(捲動中冒出貼片是噪音) |
| 互動元素 `focusin` | 開貼片(鍵盤使用者走 Tab 也要看得到) |
| 選起來一段文字(停 250ms) | **立刻**開貼片,不等停留門檻 |
| 按住 `Alt` | 可見區內所有 UI 標籤同時顯示(沿用既有的掃視語彙) |

180ms 是「掃過去」與「停下來看」的分界。低於這個值,滑鼠橫掃導覽列會沿路
閃出一整排貼片 —— 那是 tooltip 最典型的做壞法。
80ms 的關閉延遲則是為了在相鄰項目之間移動時不閃爍。

「已開著就立刻換」是 tooltip group 的標準行為:第一次要等,之後不用。
使用者已經表達過「我在看這一排」了。

### 4.2 放置

依序試,第一個放得下的就用:

1. 標籤下方,左緣對齊,間距 4px
2. 標籤上方,左緣對齊
3. 標籤右側,垂直置中
4. 標籤左側,垂直置中
5. 夾回視窗內(最後手段),但仍然貼著標籤

**永遠不放在標籤自己的矩形上。** 那會變成疊翻,而且會蓋掉原文。
視窗外一律不允許 —— 貼片跑到摺線下就等於沒有。

貼片用 `position: fixed`,座標在 hover 當下由 `getBoundingClientRect()` 算,
捲動時直接關掉。這**故意**不走疊翻那套 document 座標 + 捲動自我修正:
貼片是暫態的,不需要跟著頁面捲;而不跟著捲就沒有 build 14 那種
「JS 慢合成器一幀 → 抖動」的問題。

### 4.3 視覺

- **不透明背景**,取自來源元素的解析背景色(`resolveBackground`),取不到就用中性底
- **1px 邊框**,用既有的 `hintColor()`;邊框可以有 alpha,那不是字疊字
- **陰影**:唯一一個宣告「我不是頁面的一部分」的訊號
- 字級 `min(來源字級, 13px)`,永遠不比原文大
- 左緣 2px 的**階層條**,沿用提示線的語彙:L0 斜紋、L1 實線、失敗警示色
- `max-width: 22em`,超過就折兩行
- 淡入 120ms;`prefers-reduced-motion` 時直接出現

### 4.4 狀態與替換

- 一送出就開貼片,內容先是 `⋯`。**不開空貼片** —— 空的貼片看起來像壞掉
- L0 回來 → 填字
- L1 回來 → **只在貼片關著時換**。開著的時候掛在 `pendingSwap`,關掉再套用。
  貼片只有 4–8 個字、閱讀時間不到半秒,在使用者眼皮下換掉就是 §4.3
  「不得替換使用者當前正在互動的區塊」講的那件事
- 兩層都失敗 → 貼片顯示原文 + 警示色階層條(而不是消失)。
  「翻不出來」要看得見,和紅色提示線一致

### 4.5 A11y

- 疊層整層 `aria-hidden` 不變:貼片是原文的重複,不該被朗讀兩次
- `focusin` 觸發讓鍵盤使用者拿得到同樣的資訊
- 不搶焦點、不吃事件(本來就 `pointer-events: none`)

### 4.6 兜底:指到什麼就翻什麼(實作時追加)

掃描出來的 label 只涵蓋互動元素,但使用者的心智模型是「我指到什麼就翻什麼」。
所以 hover 的解析順序是三層:

1. 內文區塊 → 它有自己的畫法(疊翻),不出貼片
2. 掃描到的 UI 標籤 → 貼片
3. **臨時加翻** → 往上找自己就有文字的最近祖先(≤ 6 層、≤ 240 字、
   不是容器、不是目標語言),當場建單元、當場翻

再上面還有一層:**選取**。hover 找的是元素,而使用者想知道的可能是
一句話的一半、或跨越好幾個元素的一段。選取是最明確的「我要這一段」,
所以錨點跟著 `Range` 走(`anchorOverride` WeakMap),而且不等停留門檻。

240 字是分界:再長就是段落,那是疊翻的守備範圍,塞進貼片只會變成一面牆。

## 5. 成本

加翻的量級和內文完全不同:一頁可能有 30–80 個 UI 標籤,但每個只有幾個字。

- **L0 免費**,所以 Alt 掃視可以一次把可見區全部翻掉
- **L1 由注意力驅動**:只有停留超過 600ms 的那一組才送。
  使用者不會停在 80 個標籤上
- **同一段文字只送一次**:去重做在**送出層**不是偵測層 ——
  卡片牆上十二張卡都寫「詳細を見る」,十二個都要能 hover,但只送一次 API,
  回來散給所有同文字的單元(見 deviations §AX,這一條是踩過才長出來的)
- **按組批次**:hover 一個標籤,把**同一個容器裡的其他互動元素**一起送
  (最近的 `nav` / `ul` / `[role=menu]` / `[role=tablist]` / `[role=toolbar]`)。
  一次 batch 12 個短字串,比 12 次單筆 batch 便宜得多,而且滑到第二個時已經有了
- 每頁加翻單元上限 **200**,防病態頁面
- 沿用既有的每頁 token 上限與每日 TWD 保險絲,不另開額度

## 6. 資料模型與程式碼落點

### 6.1 型別

```ts
export type UnitKind = 'block' | 'label';   // 之後加 'region'(圖片裡的一塊)
export type UnitRole = 'heading' | 'body' | 'meta' | 'list' | 'cell' | 'label';
```

`Unit` 多一個 `kind`。**刻意不開第二個型別** —— 排程、快取、id 紀律、
失敗重試、hover 重試全部沿用,只有 `flush()` 依 `kind` 分派到不同的畫法。
開第二條管線就等於把 §6.4 的 id 三層防線再實作一次,那是 bug 的來源。

`role: 'label'` 要進 L1 的 system prompt 第 5 條:
> label 用介面語域:名詞或動詞短語、不加句號、比正文更短。

### 6.2 偵測

`detect.ts` 的 `isUiLabel()` 從「排除條件」改成「分類器」:命中的不再丟掉,
而是以 `kind: 'label'` 收進另一個清單。判定規則一字不改 —— 那個 24 字門檻
已經在真頁面上調過,不要在同一次改動裡動兩件事。

排除仍然適用的:sr-only、已是目標語言、純數字符號、沒有 client rect。
額外排除:同一段文字在頁面上出現多次時只留第一個(導覽列常常有行動版複本)。

### 6.3 渲染

`overlay.ts` 多一個 `AnnotationChip`:shadow root 裡與 `.layer` 平行的兄弟節點
(和 HUD、debug panel 一樣),因為它是 `position: fixed`,
不能待在會被 clip / transform 的 `.layer` 裡面 —— build 14 已經用
HUD 消失這件事付過學費了。

同時只存在**一個**貼片節點,重複使用。不是每個標籤一個 DOM。

### 6.4 檔案

| 檔案 | 改動 |
|---|---|
| `src/content/detect.ts` | `isUiLabel` 改成分類;候選帶 `kind` |
| `src/content/unit.ts` | `Unit.kind`;`labelBudget()` |
| `src/content/annotate.ts` | **新**:放置策略(純函式,可測) |
| `src/content/overlay.ts` | `showChip()` / `hideChip()` / 貼片 CSS |
| `src/content/index.ts` | hover / focus / Alt 的生命週期、按組排隊 |
| `src/shared/types.ts` | `UnitKind`、`UnitRole` 加 `label` |
| `src/worker/protocol.ts` | system prompt 第 5 條加 label 語域 |
| `src/options/options.html` | 開關:加翻層(預設開)、只在 Alt 時顯示(預設關) |

放置策略抽成 `annotate.ts` 的純函式是刻意的:它是這個功能唯一有邊界條件的部分
(四個方向、視窗夾取),而且它**就是圖片翻譯要重用的那一塊**。

## 7. 為圖片翻譯鋪的路

### 7.1 共用的原語

圖片翻譯不是新功能,是**同一個加翻層的第三種 kind**:

| | `label` | `region`(圖片) |
|---|---|---|
| 一個來源元素產生幾個單元 | 1 | N(每塊偵測到的文字一個) |
| 文字來源 | DOM | 視覺模型回傳 |
| 錨點 | 元素的 client rect | 圖片 rect 內的**正規化座標** `[x, y, w, h]` |
| 放置模式 | `chip`(旁邊) | `patch`(原位) |
| 觸發 | hover / focus / Alt | hover 圖片 |

所以 `annotate.ts` 的介面從一開始就要吃「錨點矩形 + 正規化子矩形」,
而不是「元素」:

```ts
export interface Anchor {
  rect: ViewRect;              // 來源在視窗座標的矩形
  sub?: [number, number, number, number]; // 正規化子矩形,圖片用
}
export function place(anchor: Anchor, chip: Size, viewport: Size, mode: 'chip' | 'patch'): ViewRect;
```

`patch` 模式的規則不同:它**就是要蓋在 sub 上**,而且要蓋滿 ——
但只在 hover 期間。指標離開圖片,圖片立刻恢復原狀。
原則 1「不蓋原文」在圖片上讓位給原則 2「暫態優先」:
蓋住的是像素不是活文字,而且隨時可以拿回來。

### 7.2 已知的硬阻礙

**Canvas taint。** 跨網域的 `<img>` 沒有 CORS 標頭時,畫進 canvas 會污染它,
`toDataURL()` / `getImageData()` 直接丟 SecurityError。所以
**不能從 content script 讀圖片像素**。

解法:擴充功能有 `<all_urls>` host permission,**由 service worker `fetch()`
圖片 URL 拿到 bytes**,再送去視覺模型。這條路繞開 canvas 完全成立,
但要在 worker 端加:URL 白名單(只抓 http/https)、大小上限、
`data:` 與 `blob:` 的特別處理、以及**每張圖只抓一次**的快取。

**成本量級不同。** 一張圖的視覺 token 遠高於一段文字。
所以圖片**不能**沿用「hover 就送」——至少要 hover + 停留更久,
或是明確的按鍵確認。這一條留作開放問題。

**先摘低垂的果實。** 在做真正的 OCR 之前,有兩種「圖片裡的字」其實是 DOM:

- inline `<svg>` 裡的 `<text>` —— 那是真的文字節點,現在被 `NON_TEXT_TAGS`
  的 `SVG` 一刀切掉了。可以當成 `label` 處理,零視覺模型成本
- `<img alt>` / `aria-label` —— 已經有現成的描述文字,翻它比 OCR 便宜幾個數量級

這兩個應該排在真 OCR 前面。

### 7.3 開放問題(不在這次決定)

1. 視覺模型選哪個、每張圖多少錢、free 檔位的 gemma 支不支援圖片輸入
2. 觸發門檻:hover 就送?還是 hover + 一個明確動作?
3. `background-image` 與 CSS sprite 怎麼取得來源 URL
4. `patch` 的背景色:取樣區塊四周的像素?還是一律用中性底?
5. `<canvas>` 畫出來的字 —— 目前無解,明確排除

## 8. 實作順序

**這一輪(加翻:UI 標籤)**

1. `UnitKind` / `role: 'label'` / prompt 第 5 條
2. `detect.ts`:`isUiLabel` 改成分類器,產出 label 候選
3. `annotate.ts`:`place()` 四方向 + 視窗夾取,純函式 + 測試
4. `overlay.ts`:單一貼片節點、CSS、階層條
5. `index.ts`:hover / focus / Alt 生命週期、180/80/600ms、按組排隊
6. 設定開關、說明書加一節、HUD 計數把 label 分開算

**下一輪(圖片,依序)**

7. inline SVG `<text>` 當 label 處理(零成本)
8. `<img alt>` 翻譯
9. worker 端的圖片抓取管線(fetch + 快取 + 上限)
10. 視覺模型 → `region` 單元 → `patch` 放置

## 9. 驗收

這一輪做完要能說出下面每一句都是真的:

- 導覽列上停 0.2 秒,看得到中文;移開,導覽列一個像素都沒變
- 滑鼠橫掃整條導覽列,**沒有**沿路閃出貼片
- 貼片永遠在視窗內,永遠不蓋住它自己解釋的那個標籤
- 貼片蓋到隔壁按鈕時,那顆按鈕**還是點得到**
- 關掉加翻層,行為與這一版之前完全相同
- 一頁沒有停留過任何標籤時,label 的 L1 花費是 **0**
