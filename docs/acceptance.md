# 驗收(PRD §12)

自動化測試蓋得到選取規則與 id 紀律(`npm test`,28 個)。
幾何與視覺沒有自動化的辦法 —— 疊層對不對只有眼睛看得出來,
所以這裡是每次改動後照著跑一遍的清單。

## 先跑本地 fixture

`tests/fixtures/layout.html` 把難處集中在一頁,不用連網、不用等真站台改版:

```bash
npm run build
# chrome://extensions 載入 dist/,然後開:
#   file:///…/kasanemu/tests/fixtures/layout.html
```

裡面刻意放了:sticky 工具列、nav / footer、長標題、同角色不同長度的段落組、
Georgia 襯線區塊、justify、環繞浮動圖的段落、`pre`/`code`、表格、
大量短 `li`、`column-count`、自帶背景的卡片、漸層背景、深色區塊、
以及三顆按鈕(動態新增 / 移除 / 假 SPA 換路由)。

file:// 需要在擴充的詳細資料頁打開「允許存取檔案網址」。

## 固定測試站台(§12.1)

fixture 過了以後,再跑這七類真站台:

1. 一般新聞長文(段落為主)
2. 技術文件(含 `code` 區塊、側邊導覽、表格)
3. GitHub README
4. 排版花俏的產品行銷頁(大字、卡片、非標準版面)
5. 論壇 / 討論串(大量短區塊)
6. 深色主題網站
7. 一個重度 SPA(捲動載入 + 換路由)

## 通過條件(§12.2)

- [ ] 沒有任何原文從疊層底下露出(`min-height` 這條在長譯文時最容易破)
- [ ] 同一排版角色的字級完全一致(同 `font-size` 分組必須共用同一級距)
- [ ] `code` / `pre` 區塊未被翻譯
- [ ] 導覽、按鈕、頁尾未被翻譯
- [ ] 捲動流暢,無可感知的卡頓(疊層在 document 座標系,捲動不該重算)
- [ ] SPA 換路由後疊層正確重建,無殘留
- [ ] 深色網站的疊層背景與文字色正確
- [ ] 429 時有可見的降級提示,不靜默失敗(popup 與 console 都要看得到)
- [ ] 全開 → hover → 移開,無閃爍(閃爍就是 `pointer-events` 破了)

## 另外要看的幾件事

- [ ] 按住 `Alt` 全部切標註樣式,放開還原
- [ ] 失敗的區塊提示線是虛線,且 console 有一行 warn(§6.5)
- [ ] popup 的 thoughts 欄位是 **0**(不是 0 就代表 thinking 沒關掉)
- [ ] 設定頁的模型 ID 驗證會把不存在的 ID 標紅(§5.2)
- [ ] 日預算用完後,quality / balanced 停止呼叫、free 仍可用(§8)
- [ ] 重新錨定一次(改視窗寬度)後,每頁 token 計數**沒有歸零**(§8 第 3 層)
- [ ] `prefers-reduced-motion: reduce` 下疊層直接切換,不轉場
- [ ] 快取:同一頁重新載入,首屏疊層 < 150ms 出現(§10.2)

## 圖片加註(`docs/plan-images.md` §15)

自動的部分在 `npm run probe:image`(幾何、分流、lightbox 偵測、滑鼠穿透);
**這一節是人眼才看得出來的那些**。

- [ ] **不滑就是零**:按「翻譯這一頁」之後,popup 的花費沒有因為圖片增加
- [ ] ClickHouse 的 benchmark 長文:滑到一張 chart 上停半秒 → 加註浮現,
      **移開就收**(對稱律),圖角留著「翻過了」的記號
- [ ] 同一張 chart 再滑上去 → **立刻**出現(快取),花費沒有再增加
- [ ] <kbd>Alt</kbd>+點圖 → 升級,譯文就地換掉,提示線從 L0 變 L1
- [ ] **普通點擊照常導航**:圖片是連結的時候,不按 Alt 點下去要正常前往
- [ ] claude.com 那種 UI 截圖(行內縮很小):行內只出**編號圓點**,
      滑上去看得到譯文;字夠大的圖(bar chart 那種)點「⤢ 放大檢視」→
      黑窗裡**整張變成疊字**,而且花費沒有再增加(同一份譯文換個尺寸重算)
- [ ] **同一張圖上不會混用兩種樣子**:要嘛整張疊字、要嘛整張編號
- [ ] **深色底的圖表**(ClickHouse 那幾張):疊上去之後原文退到背景、
      譯文清楚讀得到 —— 不是兩層字互相打架
- [ ] 疊上去**看得出底下是原圖**(毛玻璃,不是一塊不透明貼紙)
- [ ] 毛玻璃**沒有方框**:四角與邊緣自己淡出去,不是圓角矩形加邊框加陰影
- [ ] 加註讀起來是**一團雲**:深卡 → 霧 → 白 → 字之間看不到分界,
      不是「一圈灰環包著一條白貼片」
- [ ] **標籤上下緊貼的圖**(ClickHouse 那張 469 GB):下一塊的灰底
      **不會蓋掉**上一塊的譯文和它的白暈;字和字擠在一起是另一回事
- [ ] 短標籤(`N/A` → 「不適用」)是**一行**,不會折成兩行
- [ ] **數值與產品名不會被蓋住**:長條圖上的 `5.50%`、`Deepgram Nova-3`
      維持原樣,只有標題那類真的翻了的才疊上去
- [ ] **數字加單位也不蓋**:數據卡上的 `5x` `4x`、`25GB`、`100ms` 維持原樣;
      但 `5 tips`、`Top 10`、`19 times smaller` 這種**有句子的**照常翻
- [ ] 譯文底下那片白**沒有硬邊**,不像貼了一張紙
- [ ] 整張圖都不用翻的話,圖角說「這張圖沒有需要翻的字」,不畫空的加註層
- [ ] 錨點**滑上去出貼片**:譯文 + 底下小一號的原文
- [ ] 放大檢視右邊有**註解清單**,滑過某一列圖上對應的圓點會亮
- [ ] 圖角那行「⤢ 點這裡放大讀」**看起來像可以按的**,而且**滑鼠移過去
      的時候它不會消失** —— 停在上面讀完再按,照樣按得到
- [ ] 免費檔的圖跑超過一分鐘也會回來(worker 不會在半路被回收),
      真的斷了的話 chip 說得出是哪一種失敗
- [ ] **失敗的 chip 說「點一下重試」就要點得下去**,而且點了會**真的再送一次**
      —— 不是把同一句話再印一次
- [ ] **不能重試的**(額度用完、格式讀不了)文案不叫人點,也點不下去
- [ ] **整頁截圖那種字很多的圖**:逾時之後 chip 說「點一下只翻大字」,
      點下去在半分鐘內回來,翻的是標題與大字
- [ ] **「辨識中…」的時候 Alt+click**:升級要送得出去,不是連結也不走、
      請求也不送
- [ ] 放大檢視:<kbd>Esc</kbd> 與點黑處都關得掉;關掉之後點得到底下的頁面
- [ ] ClickHouse 那種**站方自己有放大功能**的圖:我們**不出**那顆按鈕;
      點開站方的大圖,加註自己跟過去(同 src 認親)
- [ ] 日文直排的招牌 / 海報:毛玻璃染成**警示色**(讀不對但認得出來),
      不是安靜地畫出錯的譯文
- [ ] 按住 <kbd>Alt</kbd>:圖片的加註和文字疊層**一起**收起來,
      **放開之後兩者都要回來**(不必滑走再滑回來)
- [ ] 放大檢視裡按住 <kbd>Alt</kbd>:加註**掀起來**看得到原圖,放開回來
- [ ] 切到別的視窗再切回來、或按 <kbd>Alt</kbd>+其他鍵:疊層不會卡在不見的狀態
- [ ] ClickHouse 那種**圖上壓著透明按鈕**的站:不用先點開 lightbox,
      直接滑上去就會翻
- [ ] 滑過一整篇長文的圖之後,免費配額還夠用(佇列有上限、過期會取消)
- [ ] 設定 → 圖片 → 「不翻圖片」:整條路關掉,滑到圖上什麼都不會發生

## 效能怎麼量

Performance 面板錄一段捲動:

- 捲動期間不該有 `Recalculate Style` / `Layout` 的密集長條
- 改視窗寬度觸發的單次重新錨定,主執行緒佔用目標 < 16ms(500 區塊)
- 若看到 layout thrashing,先確認量測走的是 `canvas.measureText`
  (`src/content/measure.ts`),不是逐塊讀 `scrollHeight`

## 漸進式翻譯(feature.md §6)

L0 的兩道閘門先過再測這一段:`'Translator' in self` 為真,
且 `chrome://on-device-translation-internals/` 裝得起語言包。
不支援的機器上唯一要驗的是最後一條(自動退回 single)。

沿用上面全部條件,額外:

- [ ] 首屏疊層出現 **< 150ms**(L0 語言包已就緒時;popup 的「首屏」欄位)
- [ ] L1 替換時**沒有任何區塊的字級改變**(替換前後截圖比對,或看 debug 面板的溢出數)
- [ ] L1 替換時**沒有任何區塊的幾何改變**
- [ ] 純捲動通過的區塊**不產生 LLM 呼叫**:快速捲完一頁長文,
      popup 的 token 數應該幾乎不動(門檻 1500ms)
- [ ] 刻意填錯 API key → 全頁提示線維持**虛線**,popup 出現
      「L1 一個都沒回來」警示,**不得看起來像正常運作**
- [ ] 刻意把日預算設成 0 → 同上
- [ ] 快取命中的頁面**不出現 L0 → L1 的閃動**(讀過一次再重新載入)
- [ ] hover 中的區塊不被替換(hover 住一個剛排進佇列的段落,譯文回來時不該跳)
- [ ] 在不支援 Translator API 的環境下,自動退回 `single`
      且 popup 明確說「已退回」,console 不報錯
- [ ] `l0-only` 模式下完全沒有 LLM 呼叫(popup 的 token 數完全不動)
- [ ] 行內 `<code>` 在 L0 譯文裡原樣保留;佔位符掉了的區塊算失敗(提示線變色)
      而不是交出少了程式碼的譯文
- [ ] 切換管線模式後疊層正確重建,無殘留
- [ ] popup 的「本月按管線」三列數字會隨著使用分開累計(A/B 的判準)

### 兩週 A/B 怎麼跑

feature.md §2.2:每週一種模式,記錄四項。前三項擴充自己會記
(popup 的首屏時間、按管線分列的 token 與金額、替換時已離屏的比例),
第四項「有沒有被替換干擾」只能自己記 —— 而那才是決定性的。

debug 面板(Alt+Shift+D)的三欄並列是判斷「L1 值不值得那些錢」的工具:
如果多數區塊的 L1 只是把 L0 換成同義句,`l0-only` 就是正確答案。
