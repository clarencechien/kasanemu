## 0. 一句話

圖片翻譯是**加註,不是重繪**:一層透明疊膜把原文壓暗,譯文帶光暈浮在
原位上 —— 按住就看原圖。分層照抄文字管線:免費的先自動來,好的等使用者
點名再上。

## 1. 實地觀察:兩個範例頁(2026-08-25 probe)

### 1.1 clickhouse.com 的 benchmark 長文

- **44 張**可縮放圖表,每張蓋著透明的 `button.cursor-zoom-in`,點開出現
  `span.fixed.inset-0.bg-black/80` + **新的 `<img>`,src 與原圖相同**,
  置中放大(行內 802px → 黑窗 1000px)。這就是「獨立的黑窗視窗」。
- 圖走 `_next/image` 同源代理;`alt` 是檔名(沒有用)。
- 圖型:深色底 bar chart,7-8 段短文字、字大(≥18px 顯示)。

### 1.2 claude.com 的 blog 文章

- 內文圖原始 **2042×1546**,行內只顯示 **565px**(縮到 28%)。內容是
  **整頁 UI 截圖**:幾十段文字、字級落差極大、小字在行內只有 3-6px 高。
- **沒有 lightbox**,跨域(webflow CDN),`alt` 全空。

### 1.3 結論

「黑窗」不是邊角:小字圖的主要閱讀面就是放大檢視。同一套規格必須同時
吃下「字大的 chart」與「字小的截圖」。

## 2. 核心決定

### 2.1 加註,不重繪(sukemu handoff §1、§7)

v0.1 的做法是取樣背景色畫不透明 patch(重繪)。驗證台實測兩個死穴:
配色與折行永遠有例外(破版),小字縮到 11px 以下必糊。sukemu 為同一個
問題選了另一條路,而它**沒有這兩個死穴**:

> 毛玻璃 veil(`backdrop-filter: blur + saturate(.55) + brightness(1.16)`)
> 把該區原文壓暗退後,譯文(高彩度 + 白色光暈)浮在其上。
>
> (原文照錄。**這行的參數不要照抄** —— `brightness` 的方向是寫死的,
> 只在淺底上有效,實作用的是 §3.0 修正後的 `contrast()` 版本,見 §DH。)
> 不用知道背景色、不裁切原圖、譯文長一點就長一點 —— 因為這是**標註**,
> 使用者知道底下是原圖,按住(`O` 鍵 / 長按)整層掀開。

視覺紀律照搬(sukemu handoff §8):**標註色只給譯文**,一眼分得出哪些字
是加上去的;HUD 與框線用另一支冷色。kasanemu 的具體配色在 mockup 定案。

### 2.2 兩段式,與文字管線同構

| | 文字 | 圖片 |
|---|---|---|
| L0 | Translator API,本機免費 | **gemma-4-31b-it**,API 免費檔 |
| L0 觸發 | 進視窗就翻 | **hover 圖片 500ms** 自動送 |
| L1 | 檔位模型 | **flash-lite**(quality 檔可設 flash) |
| L1 觸發 | 停留 1.5s 升級 | **Alt+click**(或點 chip)明確點名 |
| 替換 | cross-fade 就地換 | 同 —— veil 不動,譯文 cross-fade |

- 「絕不自動」修訂為「**自動的只能是免費的**」:gemma $0,hover 是
  明確的注意力訊號,和文字 L0 的哲學一致。gemma 慢(實測 9-68s)——
  但這是**背景填充**,chip 顯示進度,使用者不必等它。
- 併發防呆:gemma 免費檔 15 RPM / 12k TPM 與文字 free 檔**共用配額**,
  imageQueue 對 L0 一次只跑一張,hover 亂掃不會炸配額(佇列滿了 chip
  顯示排隊中,離開 hover 超過 10s 未開跑的取消)。
- L1 是付費動作,保留估價 chip:`升級 ≈ $0.007`。
- 每網域開關:`圖片翻譯 off / hover-L0(預設) / hover-L0 + 曾譯過的自動 L1`。

### 2.3 大小字分流:veil 加註 vs 編號錨點(sukemu 的 A 疊字 / C 註解)

量尺仍是顯示字高,但兩邊都是「加註」,只是形式。
**作用域是整張圖,不是單一塊**(修正,§DH-4):逐塊判斷時每一塊單看都對,
合起來卻是兩套視覺語言插在同一張圖上,讀圖的人得同時維持兩種閱讀模式。

- 先算完整張圖每一塊的字級,再**多數決**(七成以上過門檻 = `VEIL_MAJORITY`)
  決定整張圖的形式。
- **整張走 veil 加註**:譯文就地浮在原文上。少數塞不下的塊把**框撐大**到
  放得下(`growToFit`,是 `fontSizeFor` 的反解,共用同一組常數),
  §3.2 本來就允許譯文超框 —— 不換語彙。
- **整張走編號錨點(pin)**:小圓點標在原位,**hover pin 出貼片**
  —— 直接複用 UI 標籤的 chip 管線與樣式,零新概念。
- **放大檢視**裡重算門檻:黑窗顯示更大,行內過不了的字在這裡自動
  變成 veil 加註。站方 lightbox(§2.4)與我們自己的放大檢視同理。

### 2.4 黑窗跟著 src 走

譯文快取以圖片 bytes hash 為鍵(§6)。站方 lightbox 的圖是新元素但同
src → 快取命中,加註直接跟過去且更全。沒 lightbox 的站,翻完 chip 給
`放大檢視`:overlay 全螢幕層、深底、圖 fit 置中、加註按放大座標重畫。
互動(Esc 關、點外關)走 document 層級監聽,overlay 維持
`pointer-events: none`。

### 2.5 對稱律:文字與圖片的預設面相反

|  | 預設看到 | hover 看到 |
|---|---|---|
| 文字 | **譯文**(常駐疊層) | 原文(掀開) |
| 圖片 | **原圖**(乾淨) | 譯文(加註浮上) |

理由:文字的資訊全在語言裡,不翻就讀不動,所以譯文是常駐面;
圖的資訊主體是圖形與版面,文字是輔助,所以原圖是常駐面 ——
加註常駐會讓整頁的圖都掛著標註色,閱讀時是噪音。

**所以加註不常駐**:翻譯完成(= 已快取)後,hover 圖片才浮現、移開就收,
浮現是即時的、不再打 API。圖角留一枚小 cue(`滑上來看譯文`)標記
「這張翻過了」,同時是可發現性的入口。options 提供「加註常駐」開關
給偏好相反的人。放大檢視裡加註**常駐**(進黑窗本身就是「我要讀字」)。

## 3. UI/UX 規格

### 3.0 sukemu 原型的可抄清單(handoff §7「照抄」條款)

- ~~veil 參數:`blur(1.4px) saturate(.55) brightness(1.16)`~~ ——
  **這一條抄錯了,走過三版才定案(§DH、§DJ-2)**。定案的分工是:

  | | 負責 | 手段 |
  |---|---|---|
  | 玻璃 | 讓**原文**退場 | `blur(9px) saturate(.6)` + 淺色漸層膜 |
  | 貼片 | 讓**譯文**站住 | `.itx` 自己的米白底,和底下那張圖無關 |

  重模糊不必知道底色,因為它破壞的是**筆劃**不是明度;而明度被保留下來,
  所以看得出底下是深色圖表還是白底截圖 —— 那就是毛玻璃感。代價是玻璃場
  的亮度不可預測,所以譯文不站在上面,**它自己帶底**。
  膜的**強度可調(0–0.6,預設 0.30)**,options 收一個滑桿。
  門檻由 `scripts/probe-veil.mjs` 在 `npm run check` 裡守著(§13-7)。
- 譯文:`Noto Sans TC` 700、**深墨橘 `#8E2605`** 配米白貼片
  `rgba(255,252,247,.92)`。貼片是 **inline** 的 —— 寬度由字決定,
  所以短標籤往橫向長,不會折成「不適 / 用」;超過
  `SINGLE_LINE_CHARS`(10 字)才是句子,才允許折行。
- **錨點的另一半是清單**(§DJ-1):行內 hover 出貼片(譯文 + 原文小一號),
  放大檢視右邊掛註解清單。選中的列 `order:-1 + sticky`,不用 `scrollIntoView`。
- 按住看原圖:整層帶位移+模糊「掀起」(`translateY(-1.6%) scale(1.03)
  blur(4px)`),不是瞬間消失;`prefers-reduced-motion` 直接切。
- 低信心(`c < 0.9`)框線換警示色,pin 模式照樣列出(sukemu 的「待複核」)。
- **陷阱**(handoff §7 原文):圖片尺寸由 JS 算寫進 style,不要讓
  `max-width:100%` 在彈性容器裡自我糾纏;註解清單選取用
  `order:-1 + sticky`,**不要 scrollIntoView**(畫面會跳)。

### 3.1 觸發時序

1. hover 圖片(顯示 ≥ 200×100)500ms → 送 L0(免費),圖角出小 chip:
   `⌛ 辨識中(免費)`。完成 → 加註淡入,chip 變 `↑ Alt+click 升級 ≈ $0.007`。
2. Alt+click(或點 chip)→ L1。in-flight 去重;失敗 chip 轉紅
   `辨識失敗 · 再點一次重試`,重試上限 2。
3. L0 結果已在畫面上時 L1 回來 → 逐塊 cross-fade(對位用 box IoU +
   原文 echo,對不上的塊整批換)。
4. 完成後回到 §2.5 的閱讀狀態:加註只在 hover 圖片時浮現。

### 3.2 加註渲染

- 字級:模型不估(sukemu handoff §6 說「選一個別混用」——我們選幾何反推),
  而且**不能只看框高**。mockup 第一版只用框高,gemma 把整張小卡合併成
  高瘦一塊(82×70 正規化、30+ 字),字級直接爆成巨柱。定案公式:

  ```
  fs = min(框高 × 0.8, √(框寬px × 框高px / (字數 × 1.35)))
  ```

  面積項讓「多行合併的框」自動縮回去;縮完仍 < 11px 就落到 pin ——
  於是 gemma 的粗框(整卡一塊)自然變成錨點,lite 的細框才疊字,
  **兩檔的輸出粒度差異被同一條公式吸收**,不用分模型寫規則。
  直排(§4)把寬高對調。
- 譯文超框:允許超出 box(這是標註不是替換),但夾在圖片 rect 內。
- 專有名詞不翻靠 prompt;`kind:"code"` 的塊(等寬深底)不加註不算數。
- 圖片加註計入頁內狀態列獨立一格(`圖 2/3`);診斷 scope `image`。
- 匯出疊好的 HTML:veil + 譯文一併輸出(backdrop-filter 是純 CSS,可攜)。

### 3.3 chip

overlay 裡唯一 `pointer-events: auto` 的元素(觸控裝置的唯一入口)。
≤ 90×28px、只在 hover 圖片時存在、避開 `a`/`button` 的 client rect。

## 4. 資料契約與座標防呆(sukemu 實測移植)

```ts
// shared/types.ts —— 沿 sukemu Block 形狀,欄位名對齊,方便沿用工具
export interface ImageBlock {
  box: [number, number, number, number]; // [ymin,xmin,ymax,xmax] 0-1000
  text: string;    // 原文
  zh: string;      // 譯文
  c: number;       // 版面信心 0-1,< 0.9 標待複核
  v?: boolean;     // 直排,前端 writing-mode: vertical-rl
  kind?: 'text' | 'code';
}
```

- **prompt 直接要 0-1000**(Gemini 空間標註的訓練慣例)。sukemu 要 0-100,
  lite 就掉回 0-1000(ADR 0001 破法 1)—— 我們順著慣例要,實測三模型
  全部照給。
- **`normalizeBlocks()` 照樣移植**(sukemu `worker/gemini.ts`):從數值
  範圍推斷實際規格(0-1000 / 0-100 / 0-1 / 像素)再換算 —— 模型不照規格
  是**何時**發生的問題,不是會不會。換算過就 log 一筆 diag。
- **幾何夾取**:橫排字高 ≤ 框高、直排字寬 ≤ 框寬;box 夾在 [0,1000]。
- **多語串接檢查**(ADR 0001 破法 3):zh 長度 > text 長度 × 4 的塊
  標低信心 —— lite 在多語並排素材上會把多行譯文串進同一塊。
- object-fit/position 換算、`currentSrc` 為準、同 src 重錨定:同 v0.1
  (純函式 `mapBox()`,jsdom + probe 雙驗)。

## 5. 管線

```
content                          worker
───────                          ──────
hover 500ms / Alt+click           fetch bytes(≤4MB、http/https、每 URL 一次)
  │ {url, naturalW/H, tier}        │ OffscreenCanvas decode,長邊 >1536 縮
  │                    ──▶         │ bytes SHA-256 → 快取(含 tier 檔)
  │                                │ miss → 視覺呼叫(schema、normalizeBlocks)
  ◀── {blocks[], hash}             └ 寫快取
veil/pin 渲染 + 同 src 重錨定
```

- `imageQueue` 與文字佇列分開(token 量級不同),同一套 queuelogic 純
  函式;L0 lane 併發 1、L1 lane 併發 2。
- 一張圖一請求,不 batch。
- P1/P2 兩趟制(sukemu §5)**不移植**:那是為譯註與在地化服務的,
  kasanemu 的圖片加註不產譯註;單趟就地翻。若日後品質不夠再開 P2,
  介面留在 vision.ts 的回應後處理。

### 5.1 沒有回音的時候(補,§DI)

管線圖上畫的是成功路徑。每一個箭頭都可能不回來,而**「卡住」不可以是
一個能永久停留的狀態**。四道防線,由內而外:

| 層 | 常數 | 治的是 |
|---|---|---|
| 抓圖 | `FETCH_TIMEOUT_MS` 20s | CDN 不回應 |
| 模型 | `VISION_TIMEOUT_MS` 100s | API 連線卡住 |
| 佇列 | `ORPHAN_MS` 120s | 孤兒的年齡上限(重派仍不回來才收) |
| content | `IMAGE_WATCHDOG_MS` 180s | 訊息掉了、以上全部失效 |

四個數字**有順序**,所以住在 `src/shared/imagetiming.ts` 同一個檔案裡,
順序由 `tests/imagequeue.test.ts` 釘住(§17-bis)。

另外兩件不在管線圖上、但沒有就會整條停擺的事:

- **喚醒**:service worker 隨時被回收,佇列在 `storage.session` 裡活著不等於
  有人會去看它。圖片佇列非空時要和文字佇列**共用同一顆 `drain` alarm**
  (`syncAlarm`)—— 各自建各自的會互相 clear 掉。
- **不被回收**:alarm 是事後的救生索,keepalive 是事前的。有工作在跑時
  每 20 秒敲一次擴充 API,把 MV3 那 30 秒的閒置計時歸零 —— gemma 實測
  9–68 秒,沒有這一條等於每一張免費檔的圖都在賭。
- **孤兒 ≠ 過期**(§DJ-3):`startedAt` 分辨「還有人要看嗎」和
  「還有人在跑嗎」。派出去過的工作被 worker 回收之後要**重派**(排在新來的
  前面),不是收掉再叫使用者自己重試 —— 使用者根本沒有捲走,他在等。
- **派工不等工作**:`drainImages` 只決定要跑哪幾筆(有界),跑完的工作
  自己回頭敲門。把「還在派工嗎」這面旗子綁在請求的壽命上,
  等於一次故障換永久停擺。

## 6. 快取

鍵 = `img:{bytesHash}:{targetLang}:{modelId}`。L0/L1 各自條目(modelId
不同),L1 命中優先。值 = `{blocks, at}`。與譯文快取同 store 同匯出。
詞表 fingerprint:v1 簡化 —— 詞表變更後圖片條目視為 miss(條目少,可接受)。

## 7. 可行性實驗(2026-08-25,`scripts/probe-vision.mjs`)

三檔模型 × 兩張真實圖,schema 強制 JSON、`thinkingLevel: minimal`:

| 模型 | chart(1580×530) | 截圖(2042×1546) |
|---|---|---|
| gemini-3.5-flash | 2.0s · 7 區 | 4.7s · 29 區 |
| gemini-3.5-flash-lite | 2.8s · 7 區 | **7.3s · 53 區** |
| gemma-4-31b-it | 9.2s · 7 區 · in 367 tok | **68s** · 35 區 |

1. **三個模型都會畫框,而且在網頁渲染圖上都準**(box 誤差目測 ≤2%)。
2. **flash-lite 找字最全**(53 區,連插畫裡的迷你表格都撈到)。
3. **gemma 可用但慢** —— 所以它是 hover 背景的 L0,不是互動的主力。
4. 兩行字的區域模型會合併一框;中文譯文三家可用;專有名詞三家守。

### 7.1 與 sukemu ADR 0001 的表面矛盾,和它為什麼不是矛盾

sukemu 實測 lite 出局(框漂移、漏塊、多語串接)—— 素材是**照片**
(手寫白板、斜拍菜單)。kasanemu 的素材是**網頁渲染圖**:正拍、無透視、
字體乾淨。同一個模型在兩個域的表現可以天差地遠,兩邊的結論**都留著**:
kasanemu 選 lite 是基於自己域的實測,防呆(§4)全部照裝,
且 §13 的補量測要覆蓋照片型素材(部落格裡的實拍圖)再確認一次。

成本(牌價):lite 截圖級 ≈ **$0.007/張**、chart 級 ≈ $0.0012;gemma $0。

## 8. 詞表

路徑 A(佔位符)在圖片上不成立 —— 模型看的是像素,改寫不了來源。
只有路徑 B(prompt 詞表),`promptTerms` 同一套附在視覺 system prompt。
手冊詞表節補一句:圖片翻譯裡詞表靠模型遵守,沒有佔位符那道硬保證。

## 9. 成本閘門

- 自動的只能是免費的(L0);L1 一律明確動作 + 估價 chip。
- imageQueue 共用每日預算與 token bucket;每頁 L1 圖片預算(預設 20 張)。

## 13. 量測結果(2026-08-26,`scripts/measure-vision.mjs`)

### 13-0. 先講方法,因為第一版的方法是錯的

第一版的指標是「對每個框找最近的框算 IoU」。跑出來:

```
原尺寸  2042x1546  35 塊  IoU 1.00   ← 基準
2048px  2042x1546  58 塊  IoU 0.48   ← 同一張圖、同樣尺寸
```

**同樣的輸入跑兩次,35 塊 vs 58 塊、IoU 0.48。** 量到的是模型的隨機性,
不是解析度 —— 拿那組數字可以論證「1536 夠用」,也可以論證「縮圖有害」,
而兩句都是噪音。

改成兩件事:

1. **指標換成文字召回率** —— 「圖上這串字有沒有被讀到」。對框抖動與
   「一塊還是兩塊」的切法都不敏感,而那正是我們不在乎的部分。
2. **每組都跑噪音底線** —— 原尺寸跑兩次,參考字串只取**兩次都讀到的**。
   比噪音小的差異不算差異。

### 13-1. 縮圖敏感度 —— 結論和直覺相反

| 長邊 | lite 召回 | gemma 召回 | 輸入 token | 體積 |
| --- | --- | --- | --- | --- |
| 原尺寸 2042 | 100% | 100% | 1362 / 518 | 418KB |
| 2048 | 100% | 100% | 1362 / 518 | 418KB |
| 1536 | 97% | **93%** | 1362 / 518 | 329KB |
| 1024 | 100% | **61%** | 1362 / 518 | 170KB |
| 768 | 100% | 63% | 1362 / 518 | 107KB |

1. **輸入 token 完全不隨尺寸變。** API 端自己正規化再貼磚,所以縮圖
   **一毛錢都省不到** —— 「縮小省 token」這個前提整個不存在。
2. 密集截圖上縮圖會讓 **free 檔的召回崩掉**(1024 只剩 61%);
   lite 不受影響,照片型素材(NHK 氣象圖)兩檔在所有尺寸都 100%。
   受害的正好是「免費檔 + 小字密集」這個最需要它的組合。

**定案:`MAX_EDGE` 1536 → 2048。** 縮圖唯一買得到的是上傳體積與延遲,
賣掉的是免費檔的召回。

### 13-1b. 順手抓到的 bug:PNG 轉檔讓照片膨脹九倍

量測時看到 113KB 的 JPEG 新聞照縮到 1536 之後變成 **1048KB 的 PNG**。
原本「一律轉 PNG」的理由是「JPEG 的失真落在文字筆畫上」—— 對截圖成立,
對照片是災難:連續色調 PNG 存不了,而且來源已經失真過一次。

**定案:輸出格式跟著來源走。** PNG 來源維持 PNG,JPEG 來源用 q=0.92
的 JPEG。修完實測:照片 756KB → 269KB(不再膨脹),截圖 1387KB → 542KB。

### 13-2. thinking A/B —— **這一項用現有方法量不出來**

sukemu 的顧慮是「降 thinking 會讓框**橫向漂移**」(`adr/0001`)。
而框漂移只有 IoU 量得到,IoU 又被 §13-0 的隨機性淹沒。

要量它需要**人工標註的地面實況**(sukemu handoff §12 就是這樣做的:
十張真實照片手工標框再算 IoU)。那是另一輪的工作,不在這一輪。

現況:production 一律 `thinkingLevel: minimal`,三檔實測 thoughts 都是 0,
召回率在兩種素材上都 100% —— **沒有證據說它有問題,也沒有證據說它沒問題**。
這一格留白比填一個假數字好。

### 13-3. 照片型素材 —— lite 在我們的域裡沒問題

NHK 的氣象圖(1920×1080、日文密集、含表格)兩檔在所有尺寸召回 100%,
座標全合規。**沒有重現 sukemu ADR 0001 的 lite 出局**。

差異在素材:sukemu 的是**手持拍攝**的菜單與白板(透視變形、光影、手寫),
我們的是新聞台輸出的圖卡與網頁截圖。§7.1 寫的域差異成立 ——
但也要說清楚:**真正的手持照片我們還沒測**,NHK 圖卡不算。

### 13-4. 日文直排 —— 不能用,但認得出來

合成一張直排海報(`writing-mode: vertical-rl`),兩檔都讀壞:

```
「秋の特別展示」        → lite「開催ただし(税場盟」 / gemma「秋祭」
「開催期間 十月一日から」 → 「興展兼囊」
```

模型把直排當橫排讀,字跨欄串起來。**而且沒有一塊回 `v: true`** ——
prompt 有要,模型不給。

但它給了別的訊號:七塊裡有五六塊 `c` 掉到 0.5–0.9,加上幾何 ——
直排的框又高又窄(實測 204×15),橫排的 CJK 不會長這樣。

**定案:`looksVertical()`** —— 框高寬比 > 3 且含 CJK → 標 `v: true` 並
壓到低信心。修完實測:六塊直排全部標記,而同一張圖上橫排的英文標題
保持 `c=0.95` 且譯得正確。**不靜默做錯**(sukemu handoff §11 的態度)。

### 13-5. 詞表在視覺請求上的遵循率 —— 而且抓到 prompt 自相矛盾

三條刻意**和模型自然譯法不同**的詞(寫模型本來就會用的說法,量到 100%
也證明不了任何事):

| | 無詞表 | 有詞表(初版) | 有詞表(修正後) |
| --- | --- | --- | --- |
| gemini-3.5-flash-lite | 0/3 | 2/3 | **2/3** |
| gemma-4-31b-it | 0/3 | 2/3 | **3/3** |

初版兩檔都漏同一條:`Elasticsearch → 彈性搜尋`。原因不是模型不聽話,
是**我們的 prompt 自相矛盾** —— 規則 2 寫著「專有名詞保持原樣不翻」,
而模型認為那條比詞表大。

它沒做錯。使用者把產品名寫進詞表**並給了譯法**,那就是明確的「我要翻它」;
規則 2 是預設值,不是禁令。修法:詞表那段明講「**這條優先於規則 2**」。

修完 gemma 3/3,lite 仍然 2/3 —— **跑三輪結果一致**,不是噪音。
lite 對專有名詞的先驗更硬。

於是 §8 那句「詞表在圖片上是請求不是保證」有了數字:
**0/3 → 2~3/3,而哪個模型比較聽話和價格無關。** 手冊照這樣寫。

### 13-7. veil 可讀性(`scripts/probe-veil.mjs`,2026-08-26)

量兩個數字,四種底色**同時**要過:

- **原文殘留** —— veil 蓋上去後底下那段字對它的底還剩幾比幾。要 **< 4:1**。
- **譯文對比** —— 加註的墨色對上 veil 收出來的那片底。要 **≥ 4.5:1**。

| 素材 | 原文對比(裸) | v1 brightness | v2 contrast | **v3 玻璃+貼片** |
|---|---|---|---|---|
| 深底白字(bar chart) | 17.9:1 | **9.7 / 1.2** | 1.6 / 4.9 | 3.1 / **8.5** |
| 淺底黑字(白底圖表) | 18.9:1 | 7.2 / 6.9 | 1.4 / 7.6 | 2.1 / 8.2 |
| 中灰底深字(照片) | 3.9:1 | 2.9 / 2.7 | 1.2 / 6.1 | 1.5 / 7.7 |
| 彩底白字(品牌色塊) | 6.7:1 | 4.2 / **1.1** | 1.4 / 5.5 | 2.1 / 7.7 |

v1 那兩格粗體就是「左上那個字根本不能看」—— 不能看的是**加註本身**
(1.2:1),而原文照樣讀得到(9.7:1)。

v2 量得過但**看起來不像毛玻璃**:`contrast()` 收斂的代價是底下那張圖
一起沒了。v3 的殘留數字反而比 v2 高(2.1–3.1 vs 1.2–1.6),而那是
**刻意的** —— 原文要退到背景,不是消失(§2.1)。真正的改善在譯文那一欄:
四種底色 7.7–8.5,而且**幾乎相同**,因為墨和底都是我們自己畫的。

**v4 / v5:兩輪「拿掉硬邊」**(§DP-1、§DQ-1)。v4 把譯文貼片羽化掉,
v5 把玻璃本身的方框也化掉(中性灰 + 橢圓遮罩,`inset` -3 → -8):

| 素材 | v3 玻璃+方貼片 | v4 羽化貼片 | **v5 灰膜羽化** |
|---|---|---|---|
| 深底白字(bar chart) | 3.1 / 8.5 | 3.1 / 7.7 | 3.1 / **10.6** |
| 淺底黑字(白底圖表) | 2.1 / 8.2 | 2.1 / 8.3 | 2.2 / 8.1 |
| 中灰底深字(照片) | 1.5 / 7.7 | 1.5 / 7.4 | 1.5 / 7.2 |
| 彩底白字(品牌色塊) | 2.1 / 7.7 | 2.1 / 7.2 | 2.2 / **6.9** |

**兩輪視覺改善都幾乎不花錢**:三版的最差殘留都是 3.1,最差譯文
8.5 → 7.2 → 6.9,離 4.5 的門檻還很遠。深底那格 v5 反而好了一截 ——
中性灰把偏暗的玻璃場往上提,譯文貼片和它的落差變大。

`inset` 掃過 -3 / -8 / -12:殘留 3.3 / 3.2 / 2.9,數字上越遠越好,
但 -12 的玻璃在真圖上會溢到隔壁的圖形。**量測選不出這一格,眼睛才行**
—— 所以這裡量的是「有沒有付出代價」,不是「哪個最好」。

量的是「墨 vs 貼片」而不是「墨 vs 玻璃場」,因為設計就是這樣分工的。
退回量玻璃場的話深底那格會掉到 2.4:1 —— 所以「貼片沒生效」會直接現形。

量的是打包後 `overlay.ts` 裡那份 CSS,不在 probe 裡另抄一份(§DF);
螢幕擷圖送回頁面用 canvas 解,不多一個 PNG 解碼相依。
這支現在是 `npm run check` 的一關 —— 「只在一端有效的配方」是這次的病根,
不能讓它再溜進來一次。

### 13-8. 加註的外溢(`scripts/render-veil.mjs`,2026-08-27)

§13-7 量的是「原文退了沒、譯文讀不讀得到」。這一節量的是第三件事:
**加註在原文框以外改變了多少**。

定義:原文框以外、加註仍然改變了的最亮那一點,對隔壁沒被碰到的背景。
1.0 = 旁邊完全看不出有東西。

它為什麼要存在:使用者說「毛玻璃看起來還是一條帶子」,而膜的外緣量出來是
**1.02:1**(等於看不見)。照數字走會得到「使用者看錯了」的結論 ——
實際上是量錯了對象。他看的不是最外面那一階,是
「深卡 → 霧 → 白貼片 → 橘字」四階疊起來的輪廓(§DR-2)。

| 配方 | 原文殘留 | 譯文對比 | 外溢 |
|---|---|---|---|
| A 橢圓羽化(§DQ) | 2.8 | 6.7 | 1.02 |
| C 只有霧沒有膜 | — | — | 2.55 |
| E 只放大白羽 | 2.8 | 6.7 | 1.99 |
| **F 出貨(連續的坡)** | **2.6** | **6.7** | **2.64** |

**這個數字不是越低越好。** 1.02 的那一版是有邊的帶子,2.64 的這一版是
一團沒有邊的雲 —— 外溢是**買融入感付的錢**。所以它沒有門檻,
只在改配方的時候拿來對照。

這支腳本同時是**目視稿**:三個情境照著使用者實際回報的三張圖搭
(亮底深卡、深底連續標籤、淺底圖表),其中「深底連續標籤」刻意讓標籤
上下緊貼 —— 那是 §DR-1「灰底蓋到白底」的現場。`--sweep` 出六個配方的對照。

眼睛選得出而量測選不出的那一格(§DQ 的 inset 掃到 12 時數字最好看,
在真圖上卻溢到隔壁的圖形)從此有地方可以看。

### 14-ter. 放大檢視與每頁上限(2026-08-26 補完)

**放大檢視的入口**:`hasNativeZoom()` 認四種站方寫法 ——
`cursor: zoom-in`(ClickHouse 那顆透明按鈕的實際寫法)、連到圖片檔的
`<a>`、`[data-rmiz]`、`[class*=lightbox]`。認得出來就**不出我們的入口**,
跟著站方走。probe 四種都驗,加一個反例(連到文章的 `<a>` 不算)。

入口只在**有錨點時**出現 —— 錨點的存在就是「有字小到疊不下」的信號,
而放大檢視正是為那件事做的。全部疊得下的圖出這顆按鈕只是多一個沒用的東西。

實測(`npm run probe:image`):行內 7 疊字 / 46 錨點 → 放大後 **15 / 38**。
同一份區塊,換個尺寸重算,不重問模型。

**滑鼠穿透的兩半都驗了**:加註畫上去之後仍然點得到底下的頁面;
放大檢視開著時**反而要擋住**(整層唯一的例外)。第一版的 probe 只驗前半,
而且在放大檢視開著的時候量 —— 量出「疊層擋住滑鼠」的假警報。
兩半分開驗才問得出正確的問題。

**每頁圖片上限**(§9):預設 20 張,以**圖片內容的 hash** 去重 ——
同一張圖翻兩次(免費 → 升級)只算一張,快取命中完全不算。
擋的是「一頁翻幾張」,和 `pageTokenCap`(一頁花多少)是兩道不同的閘門:
長文四十張圖,滑過去每張都會觸發免費 L0,免費不花錢但會把配額吃光。
