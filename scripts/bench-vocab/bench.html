素材是 ClickHouse 那篇的原圖(1580×530,深底)與 gemini 實際回傳的 七塊譯文——不是示意圖,座標和字都是真的。加註的 CSS 從 production 抄過來, 參數一個沒改。
唯一的控制是顯示寬度,因為這個決定本來就是寬度的函數:拖動它,看每種語彙在哪裡塌掉。

自動規則挑一個當預設,圖角那片 chip 多一組切換——挑錯了你一鍵換掉, 不必等我猜對。下面這張是可以按的:換語彙、換素材,數字跟著動。

稀疏素材 · 7 塊

這張圖的字不多,但左右各有一大片深色留白——所以它同時是「疊字放得下嗎」和 「拉線有沒有地方擺」兩個問題的好標本。

密集素材 · 53 塊

claude.com 那張 UI 截圖,原圖 2042×1546、53 塊譯文,全部是真的。 稀疏素材上每種語彙都好看,要看的是它們在這裡怎麼塌。

三件在做這個比較台時才看出來的事

一、遮蔽面積和互動次數這兩個數字,單獨看都會騙人。 在密集素材上手動切成「疊字」,數字是遮蔽 17.2% · 0 次互動—— 兩欄都漂亮,而畫面完全不能看:長句被塞進窄框,折成一個字一行的直條。 真正分得出好壞的是第三個數字(標籤重疊 / 線交叉),那是我補上去的。

二、那個直條是 production 現在就會發生的事。 疊字模式下塞不下的塊會把字級拉到 11px、框不動,而超過十個字的貼片允許折行—— 折行點是框寬,所以窄框就折成一個字一行。這是「不適用 → 不適 / 用」的放大版, 現在還在 build 90 裡。

三、拉線是這裡唯一「稀疏時明顯最好、密集時明顯最爛」的做法。 565px 的圖表上它給你七條同時可讀、零互動、線一處不交叉; 同一套邏輯放到 53 塊上是 78 處交叉、27 條掉出畫布。 它不是備案,是另一個適用帶。

所以我不打算再猜哪一種對。自動規則挑預設,切換權交出去—— 上面那組 chip 就是它的樣子。
